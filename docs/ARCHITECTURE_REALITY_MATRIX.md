The observability boundary includes one correction to the earlier prototype.
The old `evaluate_faithfulness` implementation could score response overlap
without using its source argument. The compatibility method now requires exact
claim text in both declared source fields and the response, and the emitted
metric is named `lexical_claim_reproduction`. Its metadata states that semantic
faithfulness and accuracy are unmeasured. Domain-approved cases and a calibrated
judge remain required for semantic evaluation.

The old `evaluate_tabular_cell_fidelity` implementation accepted caller
supplied pass counts and did not read its table input. The compatibility method
now ignores those counts. It requires exact table index, row, column, and text
fixtures, and it emits `tabular_fixture_cell_match`. A passing result does not
measure general extraction accuracy. The configured phrase check now records
denylist matches and states that hallucination detection is unmeasured.

The old `evaluate_schema_compliance` implementation checked only key presence.
List input now emits `required_field_presence`. A field to type map performs a
bounded top level JSON type check and emits `typed_field_schema_check`. Neither
path claims full JSON Schema validation.

The trace state machine now separates explicit guard failure, missing evidence,
and pending review. An unmeasured check is shown as `Evidence incomplete`
instead of `Guard rejected`. Explicit publication guard failures still take
priority over other states.

## Allowed claim language

- Use **target** or **proposed** for unbuilt architecture.
- Use **configured** only for present endpoints, credentials, or artifacts.
- Use **invoked** only when a trace identifies the returned runtime and model.
- Use **measured** only with a versioned workload artifact, sample count, date,
  hardware, failures, and limitations.
- Do not infer air gap, zero egress, immutability, enterprise readiness, model
  family quality, or hardened isolation from loopback operation or passing unit
  tests.
